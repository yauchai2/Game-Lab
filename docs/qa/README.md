# QA：舊功能保護網

目的：每次更新後，確保以前做好的功能沒有被覆蓋或改壞。QA 只寫 `tools/qa/` 與 `docs/qa/`，**不修改 `src/`**；發現問題寫成記錄放在 `docs/qa/issues/`，交給原型討論串修，修完再驗。

## 出版前關卡（出測試版、出 Release 前必跑）

```
python3 tools/qa/gate.py --release  # 出 Release 前（已登記的未修問題 known-issues.json 也算失敗）
python3 tools/qa/gate.py            # 完整，約 12 分鐘（每位角色掛機 2 遊戲小時）
python3 tools/qa/gate.py --quick    # 快速，約 5 分鐘（推送時 GitHub Actions 自動跑）
python3 tools/qa/gate.py --base v0.78.0   # 指定比對基準，預設為最新正式 tag
```

結果寫到 `docs/qa/reports/latest.md`（完整模式另存 `版本-提交碼.md`）。**有「失敗」就不可出 Release**；「警告」是請作者確認是否有意的改動。

## 檢查內容

| 項目 | 指令 | 抓什麼 |
|---|---|---|
| 內容清單比對 | `node tools/qa/catalog.cjs --base v0.78.0` | 和上一個正式版比，技能、詞綴、傳奇、角色、成就、遺物、模式、更新日誌等 70 多張資料表：項目被刪 = 失敗；數值或文字被改 = 警告並列出差異 |
| 介面清單 | `browser_suite.cjs --only ui` | 上一版有的分頁、設定項目、按鈕、頁面元素，新版是否消失或變空白 |
| 冒煙 | `--only boot,viewports` | 全新開局、四種畫面大小（手機直橫、平板、電腦）開遍所有分頁，無錯誤、無橫向溢出 |
| 隨機裝備壓力 | `--only fuzz` | 4000 件隨機裝備：詞綴必須存在於詞綴表、數值有限、屬性重算不出 NaN；裝備滿載時各分頁仍可渲染 |
| 內容逐項實測 | `--only content` | 26 個技能逐個施放、37 件傳奇逐件穿戴、4 位角色逐個切換並戰鬥 |
| 深度挑戰 | `--only deep` | 4 角色 × 9 個深度（含首領）配套裝備連打（深層錯誤最常出現） |
| 掛機浸泡 | `--only soak --soak-hours 2` | 每位角色連續掛機，每 15 分鐘檢查狀態不變式、記憶體增長、有沒有卡住 |
| 離線與存檔 | `--only save` | 離線 30 秒到 3 天結算、存檔序列化往返後進度不變 |
| 舊版存檔相容 | `node tools/qa/old_saves.cjs` | 用舊版本（歷史 tag）實際玩一段並存檔，再放進目前版本載入，進度不可倒退、不可出錯 |
| 舊的邏輯測試 | gate 內 | `tools/test_*.js/cjs` 的純邏輯測試；已知失敗的列在 `known-red.txt` |

隨機測試可重現：失敗訊息會印出 seed，加 `--seed N` 重跑同一組。

## 規則

- 新功能若**有意**改了舊內容（刪除、改名、改數值），在更新日誌與 PR 說明寫清楚；警告可接受，**失敗不可**。
- `known-red.txt` 是 2026-10-27 開始時就已失敗的舊測試（多為斷言數量過期）。不在清單內的測試必須全綠。
- 每次出測試版或 Release 前跑關卡，報告貼進 PR；有未解決失敗就攔住 Release。
- 問題記錄放 `docs/qa/issues/QA-編號-簡述.md`：重現步驟、系統記錄、建議修法、狀態。
