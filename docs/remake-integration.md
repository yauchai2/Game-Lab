## 舊進度如何保留

候選規則：以G.storyFlags內一個版本標記區分舊敘事與新敘事，版本遷移由原serialize／載入owner處理，不另開第二套主線存檔。ch、end、nc與現有已探索地區旗標不清零；版本標記具體欄位名待實作時核對，不在文件先建立互相競爭的鍵。

| 舊存檔情況 | 新內容可見方式 | 必須保留／禁止的事 |
| --- | --- | --- |
| ch=0、未完成第一章 | 從橋底里入口看到新事件，既有角色配置繼續可用 | 不刪舊裝備、不重置等級、不覆蓋heroName |
| ch=1–5 | 已過章節視為完成，可在日誌回看新文本；從下一未完成章繼續 | 不重領舊章獎勵，不把已走過深度重新鎖住 |
| ch=6或end已完成 | 主線保持完成；新故事可回看，原終局活動保持可達 | 不以重讀結局再送整批獎勵，不把nc變成零 |
| 已有FIRE_SPLIT | 視為已具備首件體驗，教學可略過 | 不因首件教學再加一張；已消耗／裝在盤面亦須查同一合法持有來源 |
| 新版才首次進首區 | 新首件及委託報酬各自只結算一次 | 「看過故事」「領過物品」「用過模式」不是同一旗標 |
| 匯入、備份還原或切換角色 | 沿原存檔版本與角色自己的狀態恢復 | 無帳號後端時不承諾跨舊備份的全局去重；不可跨角色偷用另一位的ch或物品 |

同一份存檔內發獎、標記與保存要能防止重複點擊／重載；若儲存失敗，沿既有錯誤與匯出備份提示，不顯示假成功。整個物品與旗標修改須走原保存單位；不能先清旗標、下一次才補物。失敗重試不得重新roll已確定的獎勵。

## 揭示與試驗的單一方案

目前uiCartPick只對未知物顯示hint，equipCartTo裝上才寫G.seen並呼叫checkGoals。新方向改成「已持有可先揭示完整規則、再自行套用」，因此不能只把G.seen提早寫入就當接入完成：現有目標可能依鑑定計數，必須先分清獎勵是發現、實裝還是正式完成。

候選交互：取得→列入回報／原未讀→打開物件詳情揭示→檢查相容→可選隔離試驗→套用／放棄。揭示不扣材料、不卸下原卡匣、不暗中把別的技能上的卡匣搬過來；正式套用若會移動已使用的唯一張卡匣，須明示來源與目的。讀詳情不等於獲得新一張。

新試驗沿原配置資料複製隔離計算，但不直接呼叫會改正式G的還原／拾取函式來假扮沙盒。訓練或活動中的切換限制保持；未有安全隔離前先做只讀行為示意，不把看預覽算成「自己改過」成就。
