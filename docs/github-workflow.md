# GitHub 一人工作流程

目標：流程要少，`main` 永遠能玩，隨時可以放心試新東西。

## 分支

- `main`：永遠可玩，只透過 PR 合併，不直接推送。
- `claude/…`：遊戲程式（`src/`）的修改，每個任務一條。
- `codex/…`：素材、工具、文件（`assets/`、`tools/`、`docs/`），不碰 `src/`。
- `exp/…`：實驗。不滿意直接關掉 PR，分支留著當紀錄。
- 一個任務一條分支，從最新 `main` 開出，做完開 PR。分支合併後不刪（保留歷史）。

## 日常四步

1. 從最新 `main` 開分支（或讓對話自動開）。
2. 小步提交並推送，開 Draft PR。
3. PR 上的自動檢查（PR guard、QA）轉綠後，按 Squash and merge。
4. 要給人試玩：先放 `/preview/`，滿意再說「出 Release」。

## 版本與發佈

- 版本號 `0.主要.小修`：新玩法加主要，修正打磨加小修；`1.0` 留給正式版。
- 同一版本號不可發佈兩個不同內容（含 `/preview/`），發佈前先查 tag 有無被佔用。
- 開發版只放 `/preview/`（版本號帶 `-dev.提交碼`）；只有 Alan 說「出 Release」才更新正式網址並建 GitHub Release。

## 不可以做的事

- 不用 `git add .`，逐個檔案加入。
- 不用 `git merge -s ours` 後再 squash，會蓋掉別人的提交。同步時先 fetch，`main` 有新內容就以 `main` 為基底重新套用自己的提交。
- 不刪別人的分支，不改寫別人分支的歷史。

## 設定備忘

- `main` 已受保護。若要加規則，先確認不會擋住 Alan 自己與自動發佈工作流程。
- 目前自動檢查：`pr-guard`（越界檔案與版本號衝突）。`qa.yml` 隨 QA 保護網 PR 加入。
