# 離線回訪與收益基線：2026-10-22

基準：v0.31.0，來源提交 `0b315ade135897e6f9d57717a78d6bb3015f8975`。GitHub PR #6 與 gh-pages/version.json 均已核對；本批只增加驗證工具與內部文件，沒有遊戲修改或新版本發佈。

## 結論

正式離線函式在本輪範圍內能正確保留待選、單次入帳、保存重載及維持六小時上限。三條城市均只完成出發時的一次遠征，不自動消耗憑證開中樞或使用材料合成。七項針對性回歸與二十五個回訪樣本通過。

平衡仍有值得處理的風險：預設新手完全不操作、連續推進六小時，五個種子均滿倉並集齊九款核心，死亡 117–160 次。這是首次長離線壓力測試，不是正常玩家、其他職業或成形構築的代表，也不等同長期經濟已完成驗證。

## 方法與重跑

```bash
node tools/test_offline_return.cjs
node tools/probe_offline_returns.cjs /tmp/game-lab-offline-return.json
```

- 探針直接載入正式 `00-grid`、資料、狀態、戰鬥與 `05-ui`，執行原 `catchUp`／`update`／`pickup`／`serialize`／`applySave`；沒有直接加獎勵或替角色清怪。
- 只替換 DOM、音效、儲存與排程 IO。catchUp 的八毫秒分批及 0.2 秒模擬步長沿用原函式，排程回呼以隔離佇列完成；不載入渲染器。
- 固定牆鐘與 LCG 種子 11、29、83、127、251。預設角色、初始裝備及盤面，兩分鐘／六小時各測手動與自動，共二十例；種子 11 另測兩種選擇設定的十二小時回訪，共二例。
- 三條城市另以 50 級、最深 12、有限天賦及三主動技能配置，各測六小時，共三例。預先持有三區碎片、殘晶及中樞憑證，確認回訪不自動花料或重新出發。憑證是 0／1 旗標。
- 使用四個獨立執行緒；每個情境完成即原子保存 checkpoint。重跑相同路徑只重用來源指紋與情境版本一致的結果，成功才移除 checkpoint。
- 原始逐例結果、來源 SHA-256 及各指標分位數見 [results.json](offline-return-2026-10-22/results.json)。每組只有五個樣本，P10／P90 採線性插值，不能當成人口估計。

## 正確性覆蓋

七項快速回歸：真實戰鬥後的手動待選與重載、自動待選精確消耗、地面金幣／點數一次入帳、六十秒折減門檻、重疊結算拒絕重做、無摘要仍保存、儲存失敗仍可恢復遊戲並回報保存失敗。

長時樣本逐例檢查收益有限且非負、倉庫／地圖容量、地面待拾清空、保存一次及重載後所得資源／待選不變。applySave 會正常化初始裝備 UID、空收藏與城市資料，因此不把整份 JSON 位元組完全不變當成一般重載契約。

兩個上限對照在相同種子與選擇設定下，十二小時回訪的完整保存狀態與 RNG 終態，均和六小時完全相同。這只驗證六小時上限，不是十二小時收益已開放。

三條城市均完成一次、取得該區 14 枚碎片，三區憑證仍保留；最高階與中樞通關數沒有提升，碎片／殘晶沒有被自動製作扣走。這驗證單次出發與資源邊界，不能據此宣稱城市難度平衡。

既有拼圖、UX、收藏／離線、擴充、機制與配裝邏輯套件重新執行通過；城市 24 組進度邏輯亦通過。沒有因本次工具／文件改動重建或重新發佈遊戲。

## 下一批具體工作

1. 比較現行結算末尾選卡，與僅在玩家已開啟 autoCard 時於模擬過程套用選卡的候選。必須保持關閉時全部待選與材料不被自動消耗；先量測收益及死亡差異，不能只宣稱「較即時所以較好」。
2. 以相同裝備與種子，比較持續推進、安全刷怪及死亡回退策略，再加入成形構築與其他角色。死亡目前會退一層，但仍自動推進；是否應提供較穩定的掛機策略需由比較證據決定。
3. 檢查遺物待選數量是否誇大實際剩餘選擇，並檢視滿倉回收、九款核心首輪收藏及城市改機材料的後續追求。普通裝回收計數同時包含拾取過濾，不應全部叫作「手動清包負擔」。
4. 分離渲染／音效與玩法 RNG，再做前後景收益分布比較。現有渲染晃動及音效初始化仍會呼叫共用 Math.random；本探針沒有證明兩者等價。

## 驗證界線

沒有新增 Safari、觸控、FPS、長時間記憶體、報讀器、真人七／十四天回訪或所有職業流派驗收。JSON 中 localComputeMs 僅記錄本機探針運算耗時，受並行負載影響，不能拿來估算手機結算時間或遊戲幀率。

GP-A03 的程式級長時回訪與重載部分取得本輪證據；GP-B01 仍只是預設新手的五種子基線。其他流派、視覺 RNG 分離、長期經濟及真機待辦仍保留未完成。
