# 打造、角色文案與戰場血條交接

狀態：**已完成來源審查與離線互動樣板，等待原型討論串接入；未修改正式遊戲。** 基底 `641c43d`，依 `docs/codex-sync-notes.md` 分工，只改 tools/docs。QA 關卡仍由 QA 討論串建立，本文件不是其通過證明。

開啟 [preview.html](preview.html) 可切換打造裝備、材料不足及血條遠近比較。全部使用檢查樣本，不讀寫遊戲存檔、不實際扣費。Native JSON 保留原文作證據，不能把其中舊字眼當成新產品文案。

## 已核實的問題與字義

- 現行 main 未搜尋到「核心重塑」；實際重複的是「核心重構」：`deviceCraftHtml()` 的傳奇升級入口及 `studioUtilitiesHtml()` 的 core 抽屜，都指向同一個 `coreRefineHtml`／`gearOperationAsk('refine', slot)`。
- 「核心」其實是傳奇裝備，不是另插的零件。但目前 37 款傳奇中，只有 `CITY_ROUTES.*.cores` 的九款支援提升物品等級，不能寫成所有傳奇都適用。
- 傳奇詞綴種類固定，但數值可重洗、階級可提升。現有「傳奇專屬 · 固定不可改」誤導，須拆成「傳奇特效」與「詞綴種類固定」。不要改平衡或存檔鍵名。

## 打造資訊架構與操作

一個裝備選擇器 → 裝備／詞綴／階級 → 單一操作列表 → 結果與成本 → 確認。拿掉底部重複的核心抽屜入口。桌面保持閱讀寬度，手機單一縱向流程；操作可兩欄，執行按鈕全寬，觸控目標至少44px。

分類「裝備強化」／「資源與補給」。風險改裝另區，保留腐化警告。補給使用既有金幣商店與配件／卡匣配方，不新增貨幣或交易。拾取規則歸背包設定，打造只提供單一連結。樣板右下的裝備樣本控制器僅供審查，不搬進產品。

| --- | --- | --- |
| 核心重構／核心重塑 | 提升物品等級 | 指定城市傳奇每次＋1，顯示目前上限 |

### 精確成本與限制

正式 UI 從既有 `craftState`／`affTierState`／`coreRefineState` 即時讀取，禁用理由也用同一狀態。`native-craft.json` 是七個原生樣本的函式輸出，不是新平衡表。

- 提升物品等級：零件 `60+3*il`、來源城市碎片 `4+floor(il/10)`、傳奇殘晶 `1+floor(il/10)`；上限 `max(8,maxDepth+2*(city.maxTier-1))`。需城市開放、支援名單、未腐化、未鎖詞綴、非挑戰／訓練、未滿上限及材料足夠。成功保留特效、詞綴種類／階級，數值不降低，重算基礎屬性。
- 詞綴升階：沿用原狀態輸出的成本與來源城市名。T2/T1/T0所需物品等級5/12/25；保留詞綴種類與階內百分位。已鎖定、等級不足、最高階分別說明。
- 重洗：只洗未鎖數值；傳奇也可洗。超出同階上限的數值需明示可能降低。
- 腐化：25%數值＋20%、25%新增詞綴（已滿則不變）、25%不變、25%數值−15%。確認前展示原生成本及不可逆限制；不自動展開高風險區。
- 失敗範例：「這件傳奇不支援物品等級提升」「已達目前物品等級上限」「先解除詞綴鎖定」「零件不足，還差 N 個」。不要用材料不足覆蓋更早的資格失敗。
- 確認：裝備名、操作、前後變化、每種材料的消耗／持有、風險。沿用 `gearOperationAsk/Confirm`、狀態戳與確認時重驗，防止換裝／開始挑戰後舊確認仍扣費。取消／Esc不改物品，焦點回觸發按鈕。完成顯示真實變化與扣費；樣板只顯示檢視完成，不模擬成功交易。

## 角色口號：刪除，不換另一句

四句全部取消：「接地，再突破。」「讓節拍穿過靜默。」「確認訊號，鎖定目標。」「啟動，保持連線。」

來源 `characters-data.js` 的 quote 欄位與三個輸出面：

2. `05k-phone.js` 自我介紹 `.phs-q`：移除整段；不可留下「…」。保留身份資料。

原型 owner 應搜尋所有 `.quote`／`quote` 消費點，四職業逐個檢查角色、外觀、手機、職業資料、選角；保留職業名稱、定位、被動與可操作資訊，取消裝飾口號及其空容器，不只是CSS遮住。資料鍵不涉及角色存檔遷移。

## 血條實作規格

`04-render.js` `overlay()` 現在所有受傷普通怪常駐血條，角色另有重複世界條，首領亦有世界條。高度在SVG座標設硬下限並帶粗圓角，再被視框比例放大；本次原生1280px樣本的底條高約24.97 CSSpx、填色15.36px，三種鏡頭距離均未變薄。30怪樣本出現31條／62個矩形。不要把程式中的5誤當作最終CSS像素。

`tools/healthbar_review_policy.js` 是可執行幾何策略參考，不是已安裝渲染器：

- 玩家生命沿用既有 HUD，移除重複角色世界條。樣板獨立 HUD 是示意，正式版不可再疊一個玩家 HUD。
- 首領用固定上方的薄生命讀數，保留名字、精確目前／最大生命及階段；不要粗世界條橫跨首領。樣板百分比需接入既有真數值，不新增假狀態。
- 普通怪只在受擊後約1.2秒、目前戰鬥目標、精英或生命≤20%時優先。近期受擊以渲染私有 WeakMap 記錄生命下降／傷害事件，不靠受擊閃光倒數常駐，不寫存檔。死亡／離場移除。
- 依真實投影尺寸而非世界固定尺寸：世界條1–2 CSSpx；寬約投影寬×0.65，普通8–28px、目標最少18px、精英最多34px。移除現有厚度硬下限與粗膠囊圓角，保留暗底和色差。
- 以可見普通怪投影高度中位數分級：<40px最多2條、<70px最多4條、其餘最多6條。目標優先，然後精英、近期受傷、危急。這是可調顯示參數，不改AI／選敵。
- 保留 `streetCreatureBarAnchor` 的實際變換幾何定位。條放模型投影頂部上方3px；避其他角色／條，最多再上移6px，無空位就抑制低優先項。不能把血條移到遠離角色的位置；目標被遮時用固定目標讀數保留資訊。
- 避開既有HUD／螢幕邊界，依 resize 和真實 CSS / DPR 坐標重算；不要靠縮整個 SVG 或全頁像素濾鏡來變薄。樣板44px預留是獨立預覽座標，正式版讀取實際HUD矩形。
- 護盾只給優先目標額外1px短條／固定讀數，不讓每隻怪再翻倍疊條；不改護盾數值。樣本沒有護盾，**護盾與大型首領仍須接入後驗收**。
- 不依賴 hover，手機也能讀目標；世界條非互動、不逐格向螢幕閱讀器報生命變動。固定HUD沿用可存取名稱，緩節奏更新文字。

## 驗證與限制

`node tools/inspect_craft_health.cjs` 用 Chromium/SwiftShader 的 fresh 暫停遊戲抽取七件裝備狀態、三種 zoom（.45/.9/1.8）的30怪真實場景／模型投影。怪物配置及近期受傷是控制樣本，不代表自然觸發頻率。PNG直接從 WebGL canvas 匯出，避免把既有SVG血條或DOM HUD烘進背景。AABB包含附件／影子，是保守避讓界線。

`python3 tools/build_craft_health_preview.py` 建獨立離線HTML；`node tools/test_craft_health_preview.cjs` 驗證320/390/768/1024/1440寬、七種裝備、15組幾何佈局、無水平溢出、材料不足、傳奇資格、取消焦點回復、無localStorage變化及封鎖外部子資源後仍可載入。結果見 `validation.json`。
