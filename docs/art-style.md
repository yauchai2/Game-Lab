# Idle Hero 美術風格規範

遊戲的畫面全部沿用 Colorfigures 的語言：手工墨線、三階平塗、藍色投影、等距視角、暖紙底。原規範寫的是日常物品（機身、零件），這份文件把它翻譯成遊戲裡的人物、怪物、場景、掉落物與介面。畫圖的共用工具在 `src/core.js`（引擎，不要改）與 `src/game/04-render.js`（遊戲自己的小工具，函式名稱都以 `a` 或 `t` 開頭）。

## 1. 視覺語言

- **三階平塗光影**：所有面與曲面只用亮、中、暗三個平色塊，依朝光角度分配。固定單一光源、單一視角（正面、左側、頂面朝向觀者），不做旋轉，不做光源控制。角色與道具用 `toneI`，大型外殼用 `tone`。
- **墨線有層級**：外輪廓最粗（約 2.8），正面板輪廓次之（約 2.2），開口 1.6 到 1.8，細節 0.8 到 1.4。內線永遠比外框輕。用 `hullInk` 畫輪廓，細小零件的墨線會自動變淡，前提是零件本身夠細。
- **平藍投影**：物件下方一道扁平的藍色陰影，短（約高度一半），與物件相連，一個物件只有一道。透明材質（水晶、玻璃）的陰影降到約 45% 不透明度。用 `castShadow`。
- **手繪抖動**：輪廓帶輕微 wobble，由引擎的濾鏡負責，不要自己加。
- **暖紙底**：背景是暖色紙張，搭配場景色票，整體溫暖，不科技。

## 2. 色彩原則

- 每個角色、怪物、道具用一組同色系的亮、中、暗（`matOf('#hex')` 會自動產生），不混多色。
- 強調色要節制，只留給有功能的東西：
  - 狀態：生命紅 `#e2483d`、經驗綠 `#43c25c`、守關者紫 `#8e3fd1`。
  - 發光：火把、傳送陣、技能特效、稀有掉落光柱。
  - 玻璃或水晶：`#cfe9f0` 低透明加 1 到 2 道白色高光。
- 一個角色最多一個身體色相加兩個小面積強調色（例如英雄是藍色身體，紅圍巾和金色腰帶扣）。
- 禁止沿輪廓加深色邊條。只有墨線可以是深色，否則會被看成粗描邊。
- 裝備稀有度的顏色（普通、魔法、稀有、暗金）是遊戲資訊，可以用在掉落光柱、劍刃、護甲與介面卡片邊框，這是唯一允許的額外色彩。

## 3. 造型哲學

- **真實比例，細的保持細**：劍、棍棒、角、獠牙、火把桿要修長，關節與扣環要小，不可比真實物件更笨重。
- **簡潔勝於繁雜**：重複細線（草叢、肋骨、石柱紋路）控制在 8 到 18 條；細節用幾個清楚的形狀表達；零件對齊彼此與座標軸。任何要放大才看得懂的細節，就放大或刪掉。
- **附加零件必須明確接合本體**：圍巾尾、羽飾、角、盾牌、火把火焰都要接在身上，不漂浮，不無故貼在某個面上。
- **畫面飽滿**：取景只包住底板加上真正會動的範圍（`size` 參數）。底板只比場景大一點，多個物件之間留約最小物件寬度的空間，戰鬥走道（x 約 9 到 21）不放裝飾。
- **墨線絕不穿過別的物件**：逐物件完整畫完（填色、細節、自己的輪廓），再用 `byDepth` 由遠到近排序，近的蓋住遠的。
- **一物件一影子**：不要疊半透明與實心兩道影子。只有真的發光的東西（火把、岩漿）才加淡色光暈，而且光暈要淡。

## 4. 互動與敘事

- 每個畫面元素都有動作：英雄揮劍與施法、怪物突刺、掉落物彈跳後飛向英雄、火把閃動、傳送陣脈動。
- 東西只能沿真實路徑移動：怪物從傳送陣走向英雄，掉落物從死亡位置落地、停一下再被英雄撿起，不憑空出現。
- 每種補給都有來源：經驗、金幣與裝備來自擊殺，寶石與地圖來自掉落，不直接出現在背包裡。
- 亂序操作也要有合理回應：按了按鈕不能沒反應，不能用的選項要用 `disabled` 加 `why` 說明原因，操作結果也寫進事件紀錄。
- 場景裡的文字只用純字母與數字（`DEPTH 8`、`RIP`、`LEVEL UP`），不用 emoji 或符號。介面面板（HTML）可以用中文。
- 「如何運作」類才加標籤，遊戲預設不加。

## 5. 遊戲對應表

| 元素 | 做法 |
|---|---|
| 英雄 | 藍色身體，外觀隨裝備改變：護甲階級決定頭盔與肩甲，護甲稀有度決定身體色與羽飾，武器階級決定劍的長度，武器稀有度決定劍刃顏色，暗金劍有淡淡光暈。 |
| 怪物 | 史萊姆（顏色隨場景）、骷髏（暗色胸腔加肋骨弧線、圓盾、生鏽劍）、食人魔（圓肚、獠牙、角、釘棒）、守關者（體型 1.55 倍，紫色，戴皇冠）。 |
| 場景 | 四種：森林、沙漠、雪原、熔岩。每種有自己的底板色、道路、地面細節與六件裝飾，另外共用火把與傳送陣石柱。 |
| 掉落物 | 武器是小劍，護甲是胸甲，戒指是金環加寶石，寶石是八面體，地圖是卷軸。稀有以上有光柱。 |
| 介面 | 暖紙底，墨色描邊的卡片與按鈕，偏移的實心陰影，稍微不規則的圓角。裝備卡的邊框與陰影用稀有度顏色。 |

## 6. 品質把關

少而準，最多兩輪：

1. 看一張靜態圖：四個場景各一張。
2. 跑一輪主流程：快轉 `?sim=300`，確認升級、掉落、換裝都正常，再按一次不合理的操作（例如重鑄空欄位）。
3. 放大三倍看最容易出錯的地方：角色的手與武器接合處、石柱與火把的前後順序、掉落物。
4. 查錯誤：`<html data-errors="…">` 要是空的，並且搜尋 `NaN`。
5. 用陌生人的眼光看：有沒有漂浮零件、對不上的陰影、不可能的高度。

## 7. 新增美術時的檢查清單

- [ ] 只用三階平塗，沒有漸層。
- [ ] 外輪廓最粗，內線比外框輕。
- [ ] 一個物件一道藍色影子，與物件相連。
- [ ] 同色系亮、中、暗，強調色只給有功能的部分。
- [ ] 附加零件接在本體上。
- [ ] 重複細線不超過 18 條。
- [ ] 近的物件完整蓋住遠的物件。
- [ ] 場景文字只有字母與數字。
- [ ] 沒有新增全域名稱與 `core.js` 衝突（自己的函式加前綴）。
