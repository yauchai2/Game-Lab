# 藝術風格細則與開發計劃

Idle Hero 的視覺主軸是 **Y2K low poly 3D**，介面參考「幸福 Online」的童話泡泡視窗。本文件把參考圖歸納成可執行的規則，並排出分階段的開發計劃。總覽規範見 [art-style.md](art-style.md)。

## 一、參考圖歸納出的特徵

20 張參考圖（雕塑公仔實拍、Blender 畫面、低解析渲染、場景插畫）共通的地方：

1. **低解析、有顆粒的渲染**：畫面像 PS2 或 Dreamcast 時代，邊緣有明顯像素階梯，貼圖是低解析的色塊與簡單圖案。
2. **剪影靠「寬鬆工作褲」與「厚底鞋」**：褲管又大又長，佔身體一半以上，鞋子是圓鈍厚重的白色或灰色。
3. **頭小但表情靠大眼睛**：眼睛是手繪感的貼圖（深色上睫毛線、大高光、腮紅），不是立體眼球。
4. **小而簡化的手**：手指幾乎不分指，手掌像一塊扁平的形狀。
5. **耳機、鏈子、尖刺小飾品**：配件用銀白或亮色，點在深色與柔色之間。
6. **切面可見但不銳利**：低面數雕塑的刀痕感，面與面之間用明暗過渡，不是銳利的硬邊。
7. **天空與白霧**：上方天空藍漸層，往下變成白霧或白光，遠處是淺藍的城市剪影；地面常有淡色棋盤格。
8. **柔和的泛光**：整體偏亮，陰影是淡藍紫，不是黑。
9. **UI 與圖案帶像素感**：小物件（隨身聽、手機）的螢幕是像素笑臉，色塊乾淨。

## 一之二、酷感修正（Alan 回饋：不要幼兒可愛）

- 角色是街頭青年，不是 Q 版：約 5.5 頭高，半垂的細長眼加粗上眼線，沒有腮紅，嘴只是一條小線；髮型是藍黑長直髮與齊瀏海；白色耳機；超寬軍綠工作褲與大鞋；腰鍊與尖刺吊飾。
- 場景是都會街區，不是童話森林：馬路與斑馬線、販賣機、路燈、護欄、三角錐；樹木變少。
- 怪物眼睛變小、拿掉微笑，保持安靜、不討好。
- 介面減少粉紅，按鈕與選取色改用藍色。

## 二、詳細藝術風格

### 1. 角色比例與造型語言

| 項目 | 規則 |
| --- | --- |
| 身高 | 約 5.5 個頭高（Alan 回饋「太幼兒可愛」，取代先前的 4 頭高折衷，貼近參考圖的街頭青年比例） |
| 頭 | 小而圓的二十面體，後腦與髮型是主要體積 |
| 眼睛 | 貼圖：上睫毛粗線、虹膜漸層、兩個高光、腮紅；每個角色一種虹膜色 |
| 身體 | 短上衣露出一點腰，腰帶與鏈子是視覺焦點 |
| 下半身 | 寬鬆工作褲，褲管最寬處約是肩寬的 1.3 倍，大口袋用方塊表示 |
| 鞋 | 圓鈍厚底，鞋頭像麵包，白色為主，鞋帶用亮色小方塊 |
| 手 | 扁平，不分指，拿武器時用一個小方塊握把代表 |
| 配件 | 耳機、鏈子、尖刺吊飾，用銀白材質 `#e8eef5`，一個角色最多三件 |
| 髮型 | 以大片切面堆出，髮尾用尖角，顏色用粉彩或黑，每個稀有度有一組髮色 |

### 2. 材質與光影

- 材質：`MeshLambertMaterial` + `flatShading`，不使用貼圖光澤；眼睛、招牌、螢幕才用 Canvas 貼圖。
- 光：半球光（`#eaf5ff` 天空、`#d8c8f0` 地面）加暖白平行光（`#fff6ea`），強度比約 1:1。
- 影子：腳下柔和藍紫橢圓 `#6f7fd0`，不透明度 0.3。
- 泛光：場景底部加白霧漸層（從 `#ffffff00` 到 `#ffffffcc`），遠景邊緣變淡。
- 渲染解析度：參考圖偏低解析顆粒感，採用低解析渲染再放大（見決策 A）。

### 4. 背景與場景

- 天空藍漸層，加像素風白雲，底部白霧，遠處淺藍城市剪影（高樓、天線塔、廣告牌）。
- 地面是浮空的方形地塊，頂面可以加淡色棋盤格（每個生態一種格子色）。
- 地塊邊緣加一圈亮色滾邊，像遊戲關卡的平台。
- 每個生態 6 個固定道具位，加 20 到 30 個小裝飾（草、花、石、冰片、裂縫）。
- 場景要有「城市感」的元素：路燈、電線桿、販賣機、斑馬線，混入森林與沙漠主題，讓 Y2K 都會味出現在每個生態。（階段 3）

### 5. 怪物設計規則

- 輪廓用 1 到 2 個大球體或圓柱組成，一眼辨識，不超過 6 個部件。
- 眼睛一律用貼圖，風格分兩種：亮眼睛（可愛、史萊姆）與深色亮點眼（兇、巨獸）。
- 每個怪物有一個「數位寵物」記號：螢幕臉、像素笑臉、方塊耳朵。
- 顏色跟著生態的主色走，首領換成紫色加王冠。
- 受擊閃白、冰凍閃冰藍，死亡縮小淡出。

### 6. 介面與字體

- 泡泡視窗：白到淡藍漸層、3 px 白內框、2 px 粉彩外框、柔和投影。
- 標題緞帶：用稀有度顏色，白字加細陰影。
- 糖果按鈕：漸層加高光，按下回彈 2 px。
- 血條、經驗條：膠囊形，帶高光。
- 圖示：統一成圓角、粗輪廓 2 px、一個高光點，色票只用上表。
- 字體：圓體（Arial Rounded MT Bold、Hiragino Maru Gothic、jf-openhuninn 備援），數字加粗。
- 全形標點規則維持：中文用全形，英文標點後加一個空格。

### 7. 特效與動畫

- 特效用發光平塗球與環，不用粒子雲；每個特效最多 3 個元件。
- 動畫誇張擠壓：史萊姆壓扁、骷髏彈跳、巨獸揮棒、主角揮劍帶身體前傾。
- 待機：呼吸起伏、馬尾與緞帶擺動、耳機燈號閃爍。
- 升級、掉寶：加星星與愛心的粉彩彩帶，像童話遊戲的小慶祝。

## 三、開發計劃

每階段先完成再進下一階段；每階段結束都用無頭 Chromium 截圖，推到 PR，由使用者確認。

### 階段 0：已完成（現況）

- three.js 低面數平塗渲染，主角、三種怪物加首領、四個生態、傳送池、掉落物、特效。
- 泡泡視窗介面，藍天白雲背景。
- 驗收：已通過快轉、存檔來回測試與截圖檢查。

### 階段 1：美術基礎（渲染管線）

> 已決定（Alan）：渲染採用復古低解析顆粒。目前已實作 0.5 倍解析度加最近鄰放大，網址加 `?clean` 可看清晰版，以便對照。

- 交付物：低解析渲染管線（可切換解析度倍率）、白霧漸層、棋盤格地面選項、色票寫成單一設定檔 `src/game/palette.js`。
- 順序：先做渲染縮放與放大，再做霧，再抽出色票。
- 風險：低解析放大後文字與血條會糊，所以血條與傷害數字維持 SVG 疊加，不進低解析畫面。
- 驗收：同一場景可在「清晰」與「復古顆粒」兩種模式切換，截圖對照參考圖。

### 階段 2：角色與怪物資產

- 交付物：主角改成寬鬆工作褲、厚底圓鞋、扁平手、貼圖眼睛（上睫毛線、腮紅）、鏈子與尖刺吊飾；髮型 4 款；三種怪物各 2 個變體；兩個新怪物（每個生態一隻專屬）。
- 順序：主角 → 怪物 → 首領 → 生態專屬怪。
- 風險：部件變多會增加繪製成本，每個角色限制在 40 個網格以內，必要時合併幾何。
- 驗收：每個角色從 4 個角度截圖，沒有穿模、特徵位置正確；單角色網格數小於 40。

### 階段 3：場景

- 交付物：棋盤格地塊與滾邊；遠景城市剪影分層（2 到 3 層視差）；每個生態加城市元素（路燈、販賣機、斑馬線）；天候小動畫（雲飄、光點）。
- 順序：地塊 → 遠景 → 城市道具 → 動畫。
- 風險：遠景圖層太搶戲，需讓主角永遠最亮。
- 驗收：四個生態各有識別度，在縮小成縮圖時仍可分辨。

### 階段 4：介面

- 交付物：統一圖示組（裝備欄、技能、寶石、地圖、天賦節點）；天賦盤改成泡泡風格節點；技能與地圖視窗重排；升級與掉寶的慶祝提示；行動版排版。
- 順序：圖示 → 卡片 → 視窗 → 天賦盤 → 行動版。
- 風險：中文圓體字型在使用者裝置不一定有，需要內嵌子集字型（約 200 到 400 KB）。
- 驗收：桌面與手機寬度各截圖一組，沒有文字溢出或遮擋。

### 階段 5：玩法擴充

- 交付物：更多技能與輔助寶石、更多詞綴、多個職業的外觀與初始技能、首領機制、每日任務或成就。
- 順序：技能 → 詞綴 → 職業 → 首領機制 → 成就。
- 風險：數值失衡，需要模擬器跑 `?sim=` 檢查成長曲線。
- 驗收：模擬 1 小時與 8 小時的進度，等級與深度落在預期區間；存檔相容舊版本。

### 階段 6：效能與打包

- 交付物：實例化（相同模型共用幾何）、物件池、離線進度優化；單檔打包大小控制在 1.5 MB 內；行動裝置幀率達標。
- 風險：three.js 本身約 670 KB，需要評估 tree-shaking 或自訂打包。
- 驗收：中階手機 30 fps 以上；單檔載入少於 3 秒。

### 階段 7：Steam 準備

- 交付物：用 Electron 或 Tauri 打包；Steam 雲端存檔與成就對接；商店頁素材（截圖、短片、膠囊圖）；全螢幕與手把支援。
- 風險：授權（字型、three.js 為 MIT）、離線存檔跨版本。
- 驗收：Windows 與 macOS 各一個可安裝版本，能完整跑完新手流程。

## 四、需要使用者決定的取捨

- **A. 渲染質感**：已決定復古低解析顆粒（已實作，`?clean` 可看清晰版）。
- **B. 角色比例**：已改為約 5.5 個頭高（Alan 回饋整體太幼兒可愛，要像參考圖的酷感）。
- **C. 城市元素**：每個生態都加路燈與販賣機（Y2K 味重，奇幻味淡），或只在特定生態出現。
- **D. 介面字體**：內嵌圓體子集（質感一致，檔案增加），或使用系統字體（檔案小，各裝置外觀略有差異）。
