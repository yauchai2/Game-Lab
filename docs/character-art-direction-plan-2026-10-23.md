## 1. 主方向：Y2K 街頭角色封面 × 改裝展示台
把第一屏的記憶點集中在「大角色、巨大代號、鮮明色塊、三件隨身裝置」。角色像一張可操作的遊戲選角封面，下面接真正有用的配裝資訊。
保留藍紫窗口作遊戲共用骨架。角色舞台以深紫、鈷藍、冰藍形成強明暗對比；酸性黃與小面積角色專色用於焦點。具體色碼待參考檢視與對比檢查後定案。
材質分工：外框是硬朗復古窗口；舞台有單一銀色／半透明塑膠裝置語彙；資料是平整閱讀面。金屬和透光效果集中在裝置與主視覺，避免每張卡都反光。
視覺衝擊主要由大小、輪廓、遮擋層次與非對稱構圖形成；即使關閉動畫，仍應有辨識度。

## 2. 第一屏構圖
- 頂部一條身份列：角色本名／代號、玩家暱稱、等級與切換角色。暱稱與本名有明確標籤，身份只出現一次。
- 舞台佔角色工作區首屏約 50–60% 高度作初始設計目標；不是佔整個桌面戰場。依短屏調整，不能把操作推出首屏。
- 英文代號在背景大幅排版，人物在前景形成局部遮擋；中文名字與功能說明始終清楚。裝飾字不得遮臉、武器與按鈕。
- 鏡頭以約三分之四展示角開始，腳下單一低面數底座／接地陰影。保留頭髮、厚底鞋、專屬裝置、NULL 寵機的完整輪廓。
- 三件裝備與舞台組合成一個構圖。寬面板採角色偏左、裝備插槽右側；窄屏移至舞台下方一排。只有三槽，標籤讀實際 SLOTN，不能把裝扮部位錯當能力裝備欄。
- 右側原小手機保留一支及既有緩慢自轉，低於人物的視覺比重；提供「個人手機」文字入口，不增加漂浮手機。
- 舞台下接單一功能列：配裝、外觀；旋轉與還原角度是次級控制。天賦沿既有入口，不在首屏再塞完整天賦盤。

建議起稿以 520px 工作面板及 390px 手機為雙基準。桌面維持左戰場、右操作台。短手機尊重現有戰場大小偏好，不為放大角色私自收起戰場；以縮短舞台及下移次要資訊解決。

## 3. 四個角色的圖形人格
以下為創作提案，能力說明仍取現行 characters-data，不改玩法。
| 角色 | 舞台圖形 | 初始姿態／延續動作 | 小面積專色 |
| --- | --- | --- | --- |
| AKI | 折角電路、維修標記、斜向切面 | 單側重心，轉頭／活動手腕 | 電光藍＋訊號黃 |
| MILO | MD 圓盤、音軌刻度、等化器輪廓 | 上身跟拍與點頭 | 青綠＋紫 |
| PING | 簡訊游標、定位箭嘴、路線框 | 抬裝置查看訊息 | 橙＋冰藍 |
| NULL | 電子寵機液晶表情、電池槽輪廓 | 看向寵機、小幅互動 | 薄荷綠＋琥珀 |

每人限定一個主要圖形母題、一組專色、一個招牌姿態，避免堆滿貼紙。背景刻度是裝飾，不假冒即時數據；沒有數據來源就不顯示假的電量／訊號百分比。
姿態優先沿用已有骨架與 characterPreviewAnimate。若要新的招牌 pose，先確認骨架與現有九個動作能否支援，另列素材工作，不能承諾純 CSS 能完成。

## 4. 資訊架構
同一角色殼內切換「總覽／天賦／裝扮」，避免總覽再出兩個「角色頁與裝扮」按鈕。
| 層級 | 內容 | 呈現 |
| --- | --- | --- |
| 第一眼 | 大角色、名字、等級、三裝備、主要動作 | 首屏 |
| 配裝決策 | 直傷預估、最大生命、暴擊率、減傷 | 四個有差異大小的讀數；DPS 可為主讀數 |
| 角色理解 | 專屬技能＋被動 | 一張技能卡：名稱、效果、來源說明 |
| 深入資料 | 完整攻防、核心收藏、既有效果 | 點開詳情；保留原入口與完整內容 |
| 敘事與個人資料 | 一句台詞、故事、生日、暱稱編輯、事件 | 台詞短顯，其餘漸進展開 |

DPS 必須標「單體直傷預估」，不能改成總戰力或聲稱包含持續傷害／條件連動／角色專技。實測繼續連到既有訓練場。不存在可靠權重時不做六角雷達圖、總評 S 或通用升級箭嘴。
身份、被動、故事各保留一個資料來源。核心收藏可折疊或縮成摘要，但保留定向取得、上一件還原與收藏規則。
「下一步」最多一條，優先提示實際空槽或可用天賦點；沒有明確規則就顯示中性入口，不推斷最佳流派。

## 5. 裝備與外觀流程
裝備點選 → 同一工作區／共用詳情顯示物品、來源部位與詞綴 → 與目前裝備比較 → 明確換上 → 主舞台與數值同步更新。
比較沿用原 calc 與既有操作函式；不能依單一 DPS 判斷「全面更好」。從倉庫返回角色保留選中物品與位置，換裝不另存一份能力資料。
三個裝備格使用實際道具縮圖、名稱、稀有度文字與一項關鍵讀數。可快取 3D 靜態縮圖，不給每格開一個常駐 WebGL renderer。
裝扮模式沿用同一大角色舞台，收起攻防摘要，顯示武器／副手／飾品選款與當前外觀。能力裝備與純外觀要明確標示。
狀態完整包含：目前穿著、已擁有、試穿中、未擁有、金幣不足、購買並穿上、取消試穿。取消不改 G.cos、不扣費；購買重驗金幣並防止重複扣款。
原生格上「首字」占位改成可辨識的真實道具縮圖。未有模型的項目用現有合法簡單代用品並記錄替換，不憑空展示不存在的專武。
極稀有專武只有實際持有才標「已裝備／已擁有」。未持有時可作明確圖鑑目標，不提供假裝能立即試穿或解鎖的操作；概率讀原資料，不捏造掉落率。
角色切換視窗保留四人頭像、當前標記與具體解鎖條件；預覽選人與正式啟用分開，預覽不能寫入戰鬥角色。

## 6. 動態節奏
| 事件 | 提案動態 | 限制 |
| --- | --- | --- |
| 首次進入角色 | 代號遮罩揭示，角色短距離淡入，裝備分次亮起 | 總長約 450–650ms；資料即時可用 |
| 角色切換 | 專色／圖形快速交替，角色平滑換入 | 約 180–260ms；不讓文字隨機跳位 |
| 待機 | 既有四種不同動作，保留停頓 | 不持續自轉、不左右大幅搖擺 |
| 點裝備 | 插槽壓下＋單次短亮邊 | 約 120–180ms；不震動整頁 |
| 換裝／穿上成功 | 對應部位短亮，數值明示變化 | 動畫與成功狀態分開；失敗不播成功 |
| 背景／減少動態 | 靜態關鍵構圖 | 停止待機、掃光與裝飾位移 |

上述是待驗證的節奏目標，不是已量測結果。高頻戰鬥更新不能重播入場動畫；粒子、波形、掃光不常駐搶焦點。音效沿用使用者設定，不自動開啟音樂。

## 7. 響應式、可讀性與效能
390px 手機：身份列 → 約 280–320px 起稿舞台 → 三裝備一排 → 操作 → 四讀數 2×2。最終高度依可用工作區驗收，不硬鎖視窗高度。320px 減少裝飾與行內字數，保留完整名稱詳情入口。大字／200% 縮放改單欄。
保留 Cubic 11；透過展示字和正文的大小落差做衝擊，不對每行中文強加斜體、金屬描邊與陰影。英文代號作裝飾可另出自製圖形資產；互動與內容仍用可讀文字。
正文對比以 4.5:1、重要圖形與控制以 3:1 作驗收目標，不能聲稱目前已達標。控制至少 44px 觸控範圍，鍵盤焦點可見；拖曳旋轉有左右按鈕與還原角度替代。
保留單一內容捲動；無 hover 亦能看名稱、狀態、原因。模型載入失敗保留角色圖／文字與可操作插槽，不能整頁空白。
預覽共用 PV／dressMount／dressTick 生命週期；切角色妥善 dispose。戰場與預覽可以並存，但預覽內不增每格 renderer。非可見舞台與背景分頁停止更新；不在 G 中保存暫時鏡頭、過場與試穿。
手機 30fps 為初步目標，須真機量測；對照同場景、同畫質的現行基線，記錄幀時間與記憶體，不以本輪文件宣稱效能通過。

## 8. 執行順序與交付
1. 參考校準：打開全部新圖片、GIF；每份標「借用的構圖／材質／節奏」與「不採用」，完成逐張接觸表。未完成前不稱忠實參考。
2. 視覺探索：同一角色、同一資料、同一尺寸製作三張可比較靜態方向——街頭雜誌封面／掌機改裝座／PS1 選角舞台。主推第一種作構圖、第二種供控制材質、第三種供角色氣勢；正式稿只確立一個主構圖，不把全部元素堆在一起。
3. 定稿：一個選定方向的手機／桌面與四角色變體；連同外觀試穿、物品比較、鎖定、空槽、長名稱、讀取失敗狀態。
4. 首批實作：單一身份、角色舞台、三裝備、四讀數與兩個主要流程；先證明靜態畫面成立。
5. 第二批：四角色專屬圖形、真正裝備縮圖、試穿回饋、短過場，沿用已有待機。
6. 整合驗收：真瀏覽器、觸控／鍵盤、舊存檔、效能與視覺對照。整合前重讀最新 main，保留其他工作。dist 由整合後來源重建。

素材需求：四個角色舞台平面背景、四個代號圖形、一款共用底座、現有裝備／外觀縮圖、四人頭像。優先重用合法現有模型與材質；新增資產要記錄來源。參考圖只作設計依據，不直接當商用遊戲素材。

## 9. 驗收
- 靜態首屏能在三秒內辨認目前角色、三件裝備與配裝／外觀入口（待真人測試目標）。
- 去掉名字仍能憑姿態、裝置、圖形分辨四角色（待目視評估）。
- 查單件裝備最多一次點擊；從總覽進入外觀最多一次。
- 功能流程驗證：選角預覽不改當前角色；換裝比較／還原正確；試穿／取消不改能力或所有權；購買不足提示、防重扣與舊存檔相容。
- 320／390／768／1440px、短屏、200% 縮放無橫向溢出／遮擋／裁腳，焦點與彈窗回焦點正確。
- 四角色逐一觀察至少 15 秒，檢查頭髮、裝備、手臂、寵機穿模與相機裁切；開關減少動態、切背景再返回。
- 開關動畫後構圖仍完整；沒有假的即時數據、虛構戰力或誤導專武持有。
- 既有相關回歸與完整模型瀏覽器驗收通過後才稱已驗證。
